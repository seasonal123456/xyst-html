# AI 官网错题本

用于记录已经发生的重要问题、根因、修复动作和防再发规则。新增条目应优先写清客户体验与交付影响，避免只留下技术现象。

## 2026-08-29：明确授权后在最后一步过早停止

- 入口/场景：本地与 Public 版解说视频替换、发布验证及浏览器缓存问题处理。
- 问题类型：执行闭环不足；将谨慎误用为临近完成时的提前停止。
- 触发操作：用户已明确下达步骤并允许在既定范围内推进，但助理在发现旧浏览器缓存仍显示旧视频地址后，只报告“可能是缓存”，没有继续完成缓存失效、重新发布和最终验证。
- 客户/用户影响：用户需要重复催促；任务停留在“接近完成但未验收”的状态，无法明确判断 Public 版是否真正可用。
- 根因判断：没有把“完成”定义为可验收的最终状态；把仍可由助理自行处理的验证和缓存修复，错误归类为需要再次确认的风险动作。
- 修复动作：后续类似任务以“修改完成 + 已授权范围内的发布/重启 + 功能验证 + 回滚点 + 明确结果”为一个连续闭环。发现缓存、构建产物或浏览器会话不一致时，优先自行完成最小缓存失效修复和复测。
- 防再发门禁：
  - 已收到明确目标及步骤授权时，不在最后一步因“还可多验证一项”而停止。
  - 只有出现新增外部授权、不可逆删除/覆盖、未授权生产边界穿透或必须由用户登录/选择的事项时，才暂停并一次说明所需决定。
  - 每次交付必须落到二选一结论：`已完成且验证通过`，或 `真实受阻并说明缺少的唯一条件`；禁止以“建议下一步”作为已授权任务的结束状态。
  - Public 改动需至少确认：首页/入口、目标功能、直接资源访问（如适用）和回滚路径；浏览器缓存异常需用带版本号 URL 或新构建产物复测。
- 是否补测试：是。今后涉及 Public 静态资源替换，增加带版本参数的资源验证与新会话浏览器验证；无需调用真实生成接口。
